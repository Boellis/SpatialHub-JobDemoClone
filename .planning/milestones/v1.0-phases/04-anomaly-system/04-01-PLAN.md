Add initial state fields to the `create()` call (after `selectedZoneId: null`):
```typescript
anomalies: {} as Record<string, AnomalyScenarioState>,
scenarioAnnouncements: [] as ScenarioAnnouncement[],
```

Add these actions to the `create()` call:

**`triggerAnomaly(scenarioId)`:**
- Find scenario from ANOMALY_SCENARIOS by id. If not found, return early.
- Check if already active (phase !== 'idle' and entry exists). If active, delegate to `cancelAnomaly` instead (toggle behavior per user decision).
- Otherwise `set()`:
  - `anomalies: { ...state.anomalies, [scenarioId]: { phase: 'onset', ticksInPhase: 0, biasFactor: 0 } }`
  - Append to `scenarioAnnouncements`: `{ scenarioId, label: scenario.label, zoneName: scenario.zoneName, zoneId: scenario.zoneId, timestamp: Date.now() }`

**`cancelAnomaly(scenarioId)`:**
- Read current state for this scenario. If not present or already idle, return.
- `set()`: transition to recovery phase, preserving current biasFactor as starting point:
  - `anomalies: { ...state.anomalies, [scenarioId]: { phase: 'recovery', ticksInPhase: 0, biasFactor: current.biasFactor } }`

**`tickAnomalies()`:**
- Called at the END of each engine tick (AFTER bias has been applied to sensor values for this tick).
- For each entry in `state.anomalies`:
  - If phase is 'idle', skip.
  - Find the matching AnomalyScenario definition.
  - Increment `ticksInPhase` by 1.
  - Recompute `biasFactor`:
    - onset: `Math.min(1, ticksInPhase / scenario.onsetTicks)` -- ramps 0 to 1
    - peak: `1.0` -- holds at full crisis
    - recovery: `Math.max(0, 1 - ticksInPhase / scenario.recoveryTicks)` -- ramps 1 to 0
  - Check phase transitions:
    - onset and ticksInPhase >= onsetTicks: transition to 'peak', reset ticksInPhase to 0, biasFactor = 1.0
    - peak and ticksInPhase >= peakTicks: auto-timeout -- transition to 'recovery', reset ticksInPhase to 0, biasFactor = 1.0 (starts recovery from full)
    - recovery and ticksInPhase >= recoveryTicks: transition to 'idle', biasFactor = 0
  - IMPORTANT: Advance ticksInPhase THEN compute biasFactor THEN check transitions. This ensures smooth lerp with no frame-boundary jumps.
- `set()` the updated anomalies record.

**`dismissAnnouncement(timestamp)`:**
- Filter out the announcement with matching timestamp from `scenarioAnnouncements`.

Modify the `tick()` function:
1. Destructure `anomalies` from state alongside `zones` and `solElapsed`:
   ```typescript

   ```
2. In the inner loop where `computeNewValue` is called, pass the bias:
   ```typescript
   rawValues[sensor.sensorId] = computeNewValue(
     current?.value ?? sensor.nominalValue,
     sensor.sensorId,
     solElapsed,
     getAnomalyBias(anomalies, sensor.sensorId)

   ```
3. After `state.tick(newReadings)`, call `state.tickAnomalies()`:
   ```typescript
   state.tick(newReadings);
   state.tickAnomalies();
   ```

CRITICAL ordering: Read `anomalies` at the TOP of tick, apply bias during sensor computation, THEN call `tickAnomalies()` at the END. This ensures the current tick's bias factor is applied before advancing to the next tick's factor. Calling tickAnomalies before applying bias would skip the first tick of onset (biasFactor would advance before being read).
