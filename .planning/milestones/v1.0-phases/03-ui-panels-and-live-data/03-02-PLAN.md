**1. Create AlertBanner component** (`src/components/habitat/AlertBanner.tsx`):
Named export `AlertBanner`. No props — reads from store and manages its own alert state.

**Alert data model (internal to component):**
```typescript
interface Alert {
  id: string;           // unique key, e.g., "gb-co2-yellow"
  zoneId: string;
  zoneName: string;
  sensorId: string;
  sensorName: string;
  value: number;
  unit: string;
  level: 'yellow' | 'red';
  timestamp: number;
  dismissed: boolean;    // for auto-dismiss tracking
}
```

**Deduplication logic (critical — per CONTEXT.md, don't spam same sensor alert every 2s):**
- Maintain a `useRef<Map<string, number>>()` tracking `alertKey -> lastFiredTimestamp` for cooldown.
- Alert key format: `"{sensorId}-{level}"` (e.g., `"gb-co2-yellow"`)
- Cooldown period: 10 seconds minimum between re-fires of the same alert key. This means if CO2 stays yellow for 20 seconds, it fires once, not 10 times.
- When a sensor transitions from one status to another (e.g., yellow -> red), that's a NEW alert key, so it fires immediately.
- When a sensor returns to green, remove any active alert for that sensor.

**Store subscription and alert generation:**
- Subscribe to all zones: `const zones = useHabitatStore((s) => s.zones);`
- Subscribe to tickCount for change detection: `const tickCount = useHabitatStore((s) => s.tickCount);`
- Use `useEffect` keyed on `tickCount` to check for threshold crossings on each tick.
- On each tick, iterate all zones and all sensors:
  - If sensor status is `yellow` or `red`:
    - Compute alert key `"{sensorId}-{status}"`
    - Check cooldown map — if key exists and `Date.now() - lastFired < 10000`, skip
    - Otherwise, create an Alert and add to active alerts state, update cooldown map
  - If sensor status is `green`:
    - Remove any active alert for this sensorId (both yellow and red keys)
- Use `useState<Alert[]>` for the active alerts list.

**Auto-dismiss logic:**
- Yellow alerts: Set a `setTimeout` of 5000ms when created. After timeout, remove from active alerts.
- Red alerts: Do NOT auto-dismiss. Only removed when sensor status returns to green (or transitions to a different level).
- Clean up timeouts on unmount with a ref tracking active timeout IDs.

**Alert banner rendering:**
- Container: positioned at top-center of overlay, `top: 1.5rem`, `left: 50%`, `transform: translateX(-50%)`, `display: flex`, `flex-direction: column`, `gap: 8px`, `align-items: center`
- `pointer-events: auto` on individual alert cards (not the container — container is part of the pointer-events: none overlay)
- Each alert card:
  - Background: `rgba(10, 12, 18, 0.85)` with `backdrop-filter: blur(12px)`
  - Border-radius: 8px
  - Padding: 10px 16px
  - Left border: 3px solid, colored by zone accent color (import `ZONE_ACCENT_COLORS` from `./HabitatStructure`)
  - Yellow alert styling: border-color amber (#ffaa00), subtle amber tint
  - Red alert styling: border-color red (#ff2200), add a subtle pulsing glow animation: `box-shadow: 0 0 8px rgba(255,34,0,0.3)` pulsing with CSS animation
  - Content: "{zoneName} - {sensorName} {HIGH/LOW} - {value} {unit}" in monospace text
  - Determine HIGH vs LOW: compare `value` against sensor threshold green range. If above green.max -> "HIGH", if below green.min -> "LOW". Import `SENSOR_MAP` from constants to access thresholds.
  - Warning icon: Use a simple unicode character or SVG. Yellow: "!" in amber, Red: "!!" in red. Keep it simple.
- Slide-down entrance animation: `animation: slideDown 300ms ease-out` keyframe (translateY from -20px to 0, opacity 0 to 1)

**Stacking:**
- Alerts stack vertically. Newest at top. Max 5 visible alerts — if more, older ones get removed.
