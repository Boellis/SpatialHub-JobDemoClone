  ```typescript
  export type SensorStatus = 'green' | 'yellow' | 'red';
  export type ZoneStatus = 'green' | 'yellow' | 'red';

  export interface ThresholdRange {
    min: number;  // below this = warning/critical
    max: number;  // above this = warning/critical
  }

  export interface ThresholdConfig {
    green: ThresholdRange;   // nominal operating range
    yellow: ThresholdRange;  // caution range (wider than green)
    red: ThresholdRange;     // critical range (widest -- everything outside is critical)
  }

  export interface SensorConfig {
    sensorId: string;        // e.g., "gb-co2"
    name: string;            // e.g., "CO2 Level"
    unit: string;            // e.g., "ppm"
    type: string;            // e.g., "co2" -- for grouping/icons
    nominalValue: number;    // baseline center value for simulation
    driftRange: number;      // max drift from nominal in normal operation
    noiseAmplitude: number;  // random noise magnitude per tick
    thresholds: ThresholdConfig;
  }

  export interface ZoneConfig {
    zoneId: string;          // e.g., "grow-bays"
    name: string;            // e.g., "Grow Bays"
    description: string;
    sensors: SensorConfig[];
    position: { x: number; y: number; z: number };
  }

  export interface SensorReading {
    sensorId: string;
    zoneId: string;
    value: number;
    status: SensorStatus;
    timestamp: number;       // Date.now()
    history: number[];       // last 30 values for sparklines (Phase 3)
  }

  export interface ZoneState {
    zoneId: string;
    status: ZoneStatus;
    sensors: Record<string, SensorReading>;
  }

  export interface HabitatState {
    zones: Record<string, ZoneState>;
    solElapsed: number;      // seconds elapsed in current sol cycle
    isRunning: boolean;
    tickCount: number;
  }

  // For the Django API response shape
  export interface HabitatZone {
    id: number;
    zone_id: string;
    name: string;
    description: string;
    sensors: Array<{ sensor_id: string; name: string; unit: string; type: string }>;
    thresholds: Record<string, { green: number[]; yellow: number[]; red: number[] }>;
    position: { x: number; y: number; z: number };
  }
  ```

  Create the simulation engine and wire it to the Zustand store's start/stop methods.

  **Engine (src/simulation/engine.ts):** Create a `SimulationEngine` class (or factory function `createSimulationEngine`) that:

  1. **Tick interval:** Uses `setInterval` at 2000ms. Each tick:
     a. Reads current sensor values from the store (`getState()`)
     b. Computes new values using the algorithm below
     c. Derives sensor status from thresholds
     d. Pushes new values back to the store via `tick()` action

  2. **Value generation algorithm per sensor per tick:**
     ```
     newValue = currentValue
       + drift component (slow Brownian motion toward nominal)
       + noise component (small random jitter)
       + sol cycle component (sinusoidal based on solElapsed)
       + correlation component (from other sensors in same zone)
     ```

     **Drift:** Mean-reverting random walk. On each tick, nudge the value toward `nominalValue` with probability proportional to distance from nominal. Use something like:
     ```
     drift = (nominalValue - currentValue) * 0.02 + (Math.random() - 0.5) * driftRange * 0.1
     ```
     The `0.02` pull-back factor keeps values centered but allows extended excursions. The random component allows occasional wandering toward yellow thresholds.

     **Noise:** `(Math.random() - 0.5) * 2 * noiseAmplitude` -- pure random jitter per tick.

     **Sol cycle:** A sinusoidal wave based on `solElapsed` with period ~600 seconds (10 minutes compressed sol). Amplitude varies by sensor type:
     - Temperature sensors: +/- 2C over the cycle (warmer at "noon", cooler at "night")
     - Solar power output: +/- 15 kW over the cycle
     - Other sensors: +/- 2-5% of nominal (indirect effects)
     Use `Math.sin(2 * Math.PI * solElapsed / 600)` as the base wave. Increment `solElapsed` by 2 on each tick (matching the 2-second interval).

     **Correlation (intra-zone only):** After computing the primary sensor values for a zone, apply light coupling:
     - Grow Bays: If temperature rises above nominal, nudge humidity down slightly (and vice versa). If CO2 rises, nudge temperature up slightly (greenhouse effect).
     - Atmosphere Control: If O2 drops, nudge pressure down slightly (leak simulation feel).
     - Water Recycling: If pH drifts high, nudge TDS up slightly.
     - Power/Thermal: If power output drops, nudge coolant temp up (heat buildup).
     Correlation strength should be subtle: ~5-10% of the primary sensor's deviation applied to the correlated sensor. Do NOT make cross-zone correlations.

  3. **Threshold derivation (SIM-02):** After computing each sensor's new value, determine its `SensorStatus`:
     ```
     if value >= thresholds.green.min && value <= thresholds.green.max -> 'green'
     else if value >= thresholds.yellow.min && value <= thresholds.yellow.max -> 'yellow'
     else -> 'red'
     ```
     This is symmetric -- both too-high and too-low trigger warnings.

     **Zone status derivation:** After all sensors in a zone are computed, zone status = worst sensor status. Priority: red > yellow > green.

  4. **History tracking:** Each `SensorReading` maintains a `history` array of the last 30 values (for sparklines in Phase 3). On each tick, push the new value and shift off the oldest if length > 30.

  5. **Clamping:** Clamp all sensor values to physically reasonable bounds (e.g., CO2 can't go negative, battery charge caps at 100%). Use the red threshold range as the absolute bounds.

  **Wire to store (habitatStore.ts update):** Replace the stub `startSimulation()` and `stopSimulation()` methods:
  - `startSimulation()`: Create engine instance (store reference in module-level variable), call `engine.start()`, set `isRunning = true`
  - `stopSimulation()`: Call `engine.stop()`, set `isRunning = false`
  - Ensure `startSimulation` is idempotent (if already running, do nothing)
  - Ensure `stopSimulation` clears the interval properly (no memory leaks)
