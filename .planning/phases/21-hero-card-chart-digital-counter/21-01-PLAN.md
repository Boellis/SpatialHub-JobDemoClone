```typescript
interface AreaChartProps {
  data: number[];      // sensor.history (up to 60 points)
  color: string;       // STATUS_COLORS[sensor.status] — line color
  width?: number;      // default 100% of container (use viewBox scaling)
  height?: number;     // default 160
}
```

Implementation:
1. SVG with `viewBox="0 0 {width} {height}"` and `preserveAspectRatio="none"`, `width="100%"` to fill container.
2. Use the same point-mapping approach as Sparkline.tsx: auto-scale Y axis between `min(data)` and `max(data)` with 4px padding.
3. Render TWO elements on the same `<path>`:
   - **Fill area**: A `<path>` with `d` that starts at bottom-left, traces the data points, then closes back to bottom-right. Fill with a `<linearGradient>` (id: `area-grad-{unique}`) going from `{color}` at 0.3 opacity (top) to transparent (bottom).
   - **Stroke line**: A `<polyline>` (same points as Sparkline pattern) with `stroke={color}`, `strokeWidth="2"`, `fill="none"`.
4. Generate a unique gradient ID per instance using `useId()` from React to avoid SVG gradient ID collisions when multiple AreaCharts hypothetically render.
5. **Smooth append animation**: Use CSS transition on the polyline/path. Add `style={{ transition: 'all 0.4s ease-out' }}` on both the path and polyline elements — when data array grows or shifts, the SVG path `d` attribute recalculates and the CSS transition smoothly interpolates the visual. This is the same approach used by mission-control telemetry strips (no requestAnimationFrame needed).
6. If `data.length < 2`, render a flat line at 50% height (same pattern as Sparkline.tsx empty state) with gradient fill below it.
7. No axis labels, no grid lines, no chrome — pure data visualization.

**DigitRoll.tsx** — Mechanical digit-roll counter for hero card sensor values.

Create `src/components/tv/DigitRoll.tsx` with this interface:
```typescript
interface DigitRollProps {
  value: string;        // formatted value string, e.g. "22.5" or "800.0"
  fontSize: number;     // 48 for hero card
  color: string;        // sensor status color
}
```

Implementation:
1. Split `value` into individual characters (digits, decimal point, minus sign).
2. For each character position, render a fixed-size container (`overflow: hidden`, `height: 1.2em`, `display: inline-block`).
3. Inside each container, render a `<span>` that holds the current character.
4. **Digit roll animation via CSS**: Each digit container gets `position: relative`. The inner span uses CSS `transform: translateY(0)` and `transition: transform 200ms ease-out`. Track previous value with `useRef<string>`. On value change:
   - Compare old vs new character at each position
   - For CHANGED digits: set a CSS class or inline style that first positions the new digit below (`translateY(100%)`) then transitions to `translateY(0)`. The old digit simultaneously transitions to `translateY(-100%)`.
   - For UNCHANGED digits: no animation, stays static.
5. Use `useRef` to track previous value string. Use `useEffect` to detect changes and trigger the roll.
6. **Stagger**: Each changed digit gets a `transitionDelay` of `index * 30ms` (30ms stagger between digits — 200ms base means all 5-6 digits complete within ~350ms, which feels mechanical without being slow).
7. Non-digit characters (decimal point, minus sign) render static — no roll animation.
8. Container uses `fontFamily: 'Space Mono, monospace'` to match ZoneCard typography.
9. Add `data-testid="digit-roll"` on the outer wrapper.
10. Export: `export const DigitRoll = ...`

Both components use inline styles (no Tailwind) — matching all tv/ component conventions.

      // Primary = worst-status sensor (red > yellow > green), first match wins ties
