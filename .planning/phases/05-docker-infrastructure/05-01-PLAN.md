Create `docker-compose.yml` at the repo root with four services:

**1. `db` service (PostgreSQL 16):**
- Image: `postgres:16`
- Environment: `POSTGRES_DB: spatialhub_db`, `POSTGRES_USER: postgres`, `POSTGRES_PASSWORD: ${DB_PASS}`
- Volume: named volume `pgdata` mounted at `/var/lib/postgresql/data`
- Healthcheck: `pg_isready -U postgres -d spatialhub_db`, interval 10s, timeout 5s, retries 5, start_period 30s
- Port: `5432:5432`

**2. `biosim` service:**
- Build context: `https://github.com/scottbell/biosim.git` (builds from upstream source — DO NOT create a custom Dockerfile)
- Port: `8009:8009`
- Command override (the critical part — server CMD only starts the HTTP server, simulation requires a separate POST):
  ```
  sh -c "./bin/start-biosim-server &
         SERVER_PID=$!;
         until curl -sf http://localhost:8009/api/simulation >/dev/null 2>&1; do sleep 2; done;
         echo 'BioSim server ready, starting simulation...';
         SIM_ID=$(curl -s -X POST http://localhost:8009/api/simulation/start --data-binary @configuration/default.biosim -H 'Content-Type: text/plain');
         echo \"Simulation started: $SIM_ID\";
         wait $SERVER_PID"
  ```
  IMPORTANT: The `configuration/default.biosim` path is relative to WORKDIR inside the BioSim container. The upstream Dockerfile copies `configuration/` into the image. If it doesn't (Open Question 3 from research), we'll catch this in verification and volume-mount a local copy. Try the in-image path first.
  Also note: `curl` may not be available in `eclipse-temurin:21-jdk`. If so, use `wget -q --spider` for the poll and `wget -q -O-` for the POST. The executor should test curl first and fall back to wget if needed.
- Healthcheck: `curl -sf http://localhost:8009/api/simulation || exit 1`, interval 15s, timeout 10s, retries 6, start_period 90s (JVM needs time to start)
- working_dir: `/app` (explicit, matches upstream Dockerfile WORKDIR)

**3. `openmct` service:**
- Build context: `https://github.com/scottbell/openmct-biosim.git`
- Port: `9091:80`

Create directory `docker/` at repo root.

Create `docker/django-entrypoint.sh`:
```bash
#!/bin/sh
set -e

echo "Running migrations..."
python manage.py migrate --noinput

echo "Seeding habitat zones..."
python manage.py seed_habitat_zones

echo "Starting Gunicorn on port 8000..."
exec gunicorn spatialhub_backend.wsgi:application --bind 0.0.0.0:8000
```

Make it executable: `chmod +x docker/django-entrypoint.sh`

IMPORTANT: The existing Dockerfile copies `django_backend/` to `/app`, but the entrypoint is at `docker/django-entrypoint.sh` which is NOT inside `django_backend/`. The Dockerfile needs to also COPY the `docker/` directory. Add a single line to the existing `Dockerfile` AFTER the `COPY django_backend/ .` line:
```dockerfile
COPY docker/django-entrypoint.sh ./docker/django-entrypoint.sh
```
And ensure the command path in docker-compose.yml matches: `./docker/django-entrypoint.sh`

Alternatively (simpler): Copy the entrypoint into `django_backend/docker/` so it gets copied by the existing `COPY django_backend/ .` instruction. This avoids modifying the Dockerfile at all. Use this approach:
- Create `django_backend/docker/django-entrypoint.sh` instead
- In docker-compose.yml, the command becomes `["./docker/django-entrypoint.sh"]`

Choose the simpler approach (entrypoint inside `django_backend/docker/`) to avoid touching the Dockerfile, which is a production asset for Cloud Run.

Also: Copy `.env.example` to `.env` so the stack can run immediately:
```bash
cp .env.example .env
```
(This `.env` is gitignored and won't be committed.)
